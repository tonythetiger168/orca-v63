6. 語義對照表 (原 SVA → cycle checker 映射, 皆記於各 cov 檔頭部註解)
--------------------------------------------------------------------------------
ROB [M1] head/tail 為 local partition 指標 (0..ROB_PER_THREAD-1)
    [M2] rob_valid/complete/exception 由 rob_array[i] 欄位推導
    [M3] R8/R9 slot0 := thread_base(tid)+tail[tid]
    [M4] R13/R14 之 flush 限定 exception flush
    [M5] R16/R17 以 streak 實作 ##[1:N] 視窗
    [M6] R11/R12 只計「提交成功」的 retire: flush 同拍 DUT 優先 flush,
         rob_array_next/head_next 不提交, 該 retire 下拍重試 → 前提加 !flush_valid
CPU [C1] fetch_* := dec_valid/dec_pc/dec_block[31:0]
    [C2] decode_uop.rs1_addr → uop.rs1
    [C2b] A2 原以 uop_id 不等為代理, 但 uop_id 為 debug 欄位無驅動 (恆 0),
          改比 dispatch_uop[0/1].rob_idx (property 原意: 同拍不撞同一 ROB slot)
    [C2c] A3/A13 例外注入點: thread0 ROB head entry 以 packed
          rob_complete/rob_complete_exc 位元 force 建立 complete+exception,
          由 DUT 自己的 cmt_rob 產生真實 exception_detected→retire_exception→
          flush/redirect (flush 邏輯零造假)。原因: 本整合環境寫回路径近乎
          停擺 (head entry 永不 complete → 自然 retire ≈ 0, alu/ld/mul 通道
          2000 拍皆 timeout), 由寫回通道注入的例外永遠到不了 head。
    [C2d] A5/A6/A7/A12 的 retire 前提以 poke_retire 補齊: force 指定 thread
          head entry 的 rob_complete 位元, retire arbitration/rt_valid/rt_tid
          皆 DUT 真實硬體。A12 cover FSM (開機 1000 拍後依序 retire
          tid 0→1→2→3) 即以四次 poke 依序觸發。
    [C3] A8 之 ROB slot 用 uop.rob_idx (原誤用 uop_id)
    [C4] rob_valid/rob_complete 由 u_rob.rob_array 狀態位推導
    [C5] rob_head/rob_tail := retire port0 當下 thread 之絕對指標
    [C5b] A7 前提加 retire_valid[0]: 無 retire 時 rt_tid_w[0] 為舊值,
          指標無意義, 否則量到 stale 指標假 fail
    [C6] A3 視窗 [1:2]→[0:2]: cmt_rob 例外與 flush 同拍 (比規格更快)
    [C6b] A8/A10 的 liveness 以「全程規律 flush 節律」限界: 本環境自然
          retire ≈ 0, 若留長無 flush 尾段, 佇列年齡必超 timeout 造成
          stimulus 假 fail; 改為 flush 每 280 拍直到尾聲 (間隙上限
          560 < 1000/2000), attempts 照計、fails=0
    [C7] A13 字面 $onehot0({retire_exception,flush_pipeline}) 在本 DUT
          自相矛盾 (例外必伴 flush), 以意圖實作 (同拍唯一例外事件)

    [C9] A6/A18 原 SVA 為 uvm_warning 級: 違規計 warnings 不計 fails
    [C10] A14 前提 opcode==OP_ALU 放寬為 OP_ALU|OP_ALUI: TB 以 32B 對齊

7. 另案發現 (超出 SVA 範圍, 回報 F3 / core 整合)
--------------------------------------------------------------------------------
(a) 寫回→ROB complete 路径近乎停擺: 本 TB 環境下 ROB head entry 數千拍不
    complete (RSTDBG: occ0=210 head0=0 hv=1 hc=0 持續 3000+ 拍), alu_rv
    在 ~1300 拍後完全沉寂, 自然 retire ≈ 0。cpu_directed_tb 亦未驗證 retire。
    疑似 writeback rob_idx 路由或 issue/scheduler starvation, 屬 core 整合
    議題。SVA 側以 [C2c]/[C2d]/[C6b] 記錄並繞道量測。
(b) mul 寫回從不完成 (>2000 拍無 mul_rv, 與 tid 策略無關), PROG 中兩道
    mul 已以 add/sub 取代 (ROB in-order retire 會卡 head)。屬 (a) 之一環。
(c) ld_rv[0]/st lane 亦從不觸發 (雖 prf_wv[8:5] 有寫回) — 同 (a)。
(d) f3_core_poke_tb BUILDFAIL: TB 對 unpacked array (ld_uv/st_uv/mem_funct3)
    做階層式 force, Verilator 產生不支援的 unpacked VL_OR_W — 既存問題,
    與本次 cmt_rob 修復無關。
